# Проверка решения по критериям кейса

## 1. Понятность результата для CTO

Дашборд отвечает на четыре управленческих вопроса:

1. Что чаще всего поручают ИИ — категории, сценарии и типичные формулировки.
2. Что растёт — сравнение текущего и предыдущего периода.
3. Где возникают проблемы — отдельно проблемы запроса и результата агента.
4. Что делать дальше — приоритизированные рекомендации:
   - какие сценарии автоматизировать;
   - какие агенты развивать;
   - какие команды и чему обучать.

Экономия времени не придумывается. Она рассчитывается только при наличии
`task_completed` и `estimated_minutes_saved`. При отсутствии наблюдений
дашборд показывает ограничение данных.

## 2. Качество группировки

- Классификация: LLM с JSON-схемой и детерминированный fallback.
- Сценарии: char n-gram TF-IDF и агломеративная кластеризация внутри категории.
- Запросы категории `other` исключаются из сценариев.
- Входной порядок фиксируется для воспроизводимости.
- Качественные пороги проверяются автоматически:
  - accuracy категорий не ниже 0,75;
  - pairwise F1 сценариев не ниже 0,65.
- Дополнительно используется рукописный holdout, не связанный с шаблонами
  генератора.

## 3. Интерпретируемость

- Все категории имеют русские названия.
- Нерабочие запросы выделены в `non_work_general`.
- `other` означает только неизвестный или недостаточно определённый запрос.
- Для категории показаны назначение, саммари, топ-сценарии, примеры и проблемы.
- Для сценария показаны название, описание, типовые формулировки, риски и
  следующее действие.

## 4. Техническая реализация

- FastAPI, PostgreSQL, Alembic, отдельный worker.
- Идемпотентность по `(agent_id, external_id)`.
- JSONL читается построчно.
- Поддерживается файл до 512 МБ.
- Контекст до 100 000 токенов включительно является штатным.
- В LLM отправляется фактический запрос, а не весь 100k-контекст.
- Обработка событий выполняется конкурентно с ограничиваемым параллелизмом.
- Есть повторный анализ существующих событий после изменения классификатора.
- Есть offline fallback при недоступности LLM.
- Backend, frontend, миграции и метрики имеют автоматические проверки.
- Производственные npm-зависимости проходят `npm audit`.

## 5. Продуктовость

- Контроль покрытия данных без выдуманных KPI.
- Разрезы по агентам, командам и направлениям.
- Разделение принятия решений на автоматизацию, развитие агента и обучение.
- Поддержка outcome-полей для доказательства реальной, а не иллюзорной пользы.
- Синтетические данные явно маркируются.
- Динамика скрывается, если истории недостаточно.

## Формат сдачи

- исходный код и Docker Compose;
- инструкция запуска в `README.md`;
- генератор 35 выданных бизнес-сценариев и трёх контрольных сценариев;
- быстрый и 100k-профили;
- независимый holdout;
- веб-дашборд как итоговый отчёт.
